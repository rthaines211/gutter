## 3. App Store Connect mechanics

### A. Temporary price change for a non-consumable IAP (recommended)

Source (read): https://developer.apple.com/help/app-store-connect/manage-in-app-purchases/schedule-price-changes-for-in-app-purchases

The page covers "In-App Purchases" in general (consumables and non-consumables). It names a separate path only for non-renewing subscriptions. Roles: Account Holder, Admin or App Manager. Price changes can have "definite start and end dates" and then go back to the regular price. A start date can be any day from today to the end of next calendar year. The longest temporary change is one year.

Click path (Apple's steps, applied to Gutter):

1. App Store Connect → **Apps** → **Gutter: Comic Reader**.
2. Sidebar → **Monetization** → **In-App Purchases**.
3. Click **Gutter Pro** (`com.ryanhaines.gutter.pro`).
4. Next to **Price Schedule**, click **+**.
5. Choose **Temporary Price Change** → **Next**.
6. Start **Nov 27, 2026**, end **Dec 1, 2026** → **Next**.
7. Select countries or regions: all (or at least the base country, USA) → **Next**.
8. Base country **United States**, price **$6.99** → **Next**.
9. Check the equivalent prices Apple suggests for the other regions → **Next**.
10. Check the summary → **Confirm**.

Notes:
- Apple warns that a temporary change that includes the base country turns off automatic price adjustments in all 175 regions for those dates. That is fine for 5 days.
- Start and end times differ by region. ASC shows them in your browser's time zone and in UTC. See https://developer.apple.com/help/app-store-connect/reference/app-store-pricing-and-availability-start-times-by-country-or-region/ (read; the table did not render for me, so check it in ASC). If a date has already passed in a region, the change takes effect at once there, but it can take up to 24 hours to show.
- The page does not say that a price change needs App Review. (Inferred: it does not, and it can be set while 1.0.3 is in review.)
- In the app: the Pro sheet gets the localized price from StoreKit (`ProNotifier.product` → `ProductDetails`), so the sale price shows with no build (inferred from `lib/providers/pro_provider.dart`). Check that a sandbox or TestFlight Pro sheet shows $6.99 on Nov 27.
- Schedule it now. Changes can take up to 24 hours to show. Do not leave it to Nov 26.

### B. Offer codes for a non-consumable (other choice; this is what Indie App Sales suggests)

Source (read): https://developer.apple.com/help/app-store-connect/manage-in-app-purchases/create-offer-codes-for-in-app-purchases

- Offer codes now work for In-App Purchases, including non-consumables. A **Paid Offer** (a discounted price) or a **Free Offer** is possible. Customers need iOS 16.3 or later to redeem in the app.
- Path: Apps → Gutter → In-App Purchases → Gutter Pro → **Offer Codes** → **Create Offer**. Reference name (e.g. `BF46`) → eligibility (select all three to make it open to everyone) → regions → **Paid Offer**, $6.99 → Confirm. Then open the offer → **Create Custom Codes** → code (e.g. `GUTTERBF26`, ≤64 characters, no special characters), limit ≤25,000 per entry, expiry.
- Custom codes need the app to be Ready for Distribution and the IAP to be Approved (both are true). Codes can take up to 1 hour to work, and they expire at 12:00 a.m. PT on the expiration date. Set the expiry to **Dec 2** so Dec 1 works in all time zones.
- Redemption URL: the IAS post says the "Production Offer Code URL Template" is on the offer page (replace `CODE`). Apple's help page does not document it.
- App side (inferred): a redeemed code arrives as a `purchased` transaction on `purchaseStream`, and `ProNotifier._onPurchases` already unlocks Pro for any `purchased`/`restored` transaction that the app did not start. This is not tested. Test it with a sandbox offer code first.
- Risk: an Apple forum thread (2026) reports one-time codes for a non-consumable failing with "This promotional offer is not available": https://developer.apple.com/forums/thread/824524 (search result only, not read).
- Why A is better for Gutter: a free app with an IAP is bought inside the app. A price drop shows to everyone on the Pro sheet with no code to type, and it needs no new code path. Codes only reach people who see the link.

### C. Offers that do NOT apply to a non-consumable

- **Win-back offers:** for auto-renewable subscriptions only. Apple's news post title is "Win-back offers for auto-renewable subscriptions now available" (https://developer.apple.com/news/?id=8utnewzk; help page https://developer.apple.com/help/app-store-connect/manage-subscriptions/set-up-win-back-offers/). Search result; title read, page not opened.
- **Promotional offers / introductory offers:** auto-renewable subscriptions only (inferred from Apple's offer model; not confirmed on a page in this session).
- **Promoted In-App Purchases** (https://developer.apple.com/help/app-store-connect/configure-in-app-purchase-settings/promote-in-app-purchases, search result only): this is not a discount. It shows an IAP (up to 20) on the product page, with a promotional image. Changes can take up to 24 hours. It could put Gutter Pro on the product page during the sale. But a purchase started from the App Store must be handled by the app (StoreKit "promoted purchase" path), and Gutter has not tested that (inferred). Skip it for this sale.
- **Promo codes:** Apple stopped new IAP promo codes on 2026-03-26; offer codes replace them (search result citing https://developer.apple.com/news/?id=gf6mgrs6).
